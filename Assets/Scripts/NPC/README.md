# NPC 만들기 · 하루 일과 짜기

NPC 한 명은 **json 1개 + 스프라이트 폴더 1개**입니다. C#은 건드리지 않습니다.

```
Assets/Resources/NPC/Leona.json                     대사 · 선물 · 하루 일과
Assets/Resources/Sprites/NPC/Leona/
    Leona_sprites.png                               걷기 시트 (32x32 칸)
    Portraits/Leona_happy.png  ...                  대화창 초상화 (파일 이름 = 부르는 이름)
```

json의 `id`는 **스프라이트 폴더 이름과 똑같아야** 합니다 (`"id": "Leona"` ↔ `Sprites/NPC/Leona/`).

## 1. 그림 넣기

`Leona_sprites.png` 는 한 줄이 한 동작이고 **줄 순서가 정해져 있습니다**.

| 줄 | 동작 | 프레임 |
| --- | --- | --- |
| 1 | idle_down | 필요한 만큼 (1장도 됨) |
| 2 | idle_side | " |
| 3 | idle_up | " |
| 4 | walk_down | " |
| 5 | walk_side | " |
| 6 | walk_up | " |

왼쪽을 볼 때는 `side` 를 **좌우 반전**해서 쓰므로 왼쪽 그림은 그리지 않습니다.
칸이 통째로 비어 있으면 그 칸은 조각으로 만들지 않습니다 — 대기는 1장, 걷기는 4장처럼 섞어도 됩니다.

초상화는 `Portraits/` 에 한 장씩 넣습니다. 캔버스에 여백이 많거나 같은 그림이 여러 벌 들어 있어도
**가장 왼쪽 덩어리만** 잘라 쓰므로 Aseprite에서 내보낸 그대로 넣으면 됩니다.

그림을 넣은 뒤 잘라내기 설정(.meta)을 만듭니다. **이미 .meta가 있는 파일은 건드리지 않습니다.**

```bash
python tools/build_npc_metas.py
```

## 2. 대사에 초상화 붙이기

대사마다 `portrait` 에 **Portraits 폴더의 파일 이름**을 적습니다. `"Leona_happy"` 처럼 다 적어도 되고
`"happy"` 처럼 줄여 적어도 됩니다. 비워 두면 `defaultPortrait` 를 씁니다.

```json
{
  "id": "Leona",
  "defaultPortrait": "happy",
  "dialogues": [
    { "id": "greet", "portrait": "happy", "lines": ["안녕!"],
      "choices": [
        { "text": "응, 좋아해!", "portrait": "blush", "affection": 15, "reply": ["역시!"] }
      ] }
  ],
  "giftLines": { "lovedPortrait": "blush", "loved": ["이건 내가 좋아하는 거잖아."] },
  "itemGiftLines": [ { "itemId": "wood", "portrait": "happy", "lines": ["고마워!"] } ],
  "alreadyTalkedPortrait": "happy",
  "giftLimitPortrait": "flustered"
}
```

초상화는 대화창 **왼쪽 위 바깥**에 서서 창 테두리에 살짝 걸칩니다 (`DialogueUI`).

## 3. 하루 일과 (요일 · 계절 · 날씨별 루트)

### 왜 좌표를 안 적어도 되나

걸음 좌표를 한 칸씩 찍을 필요가 없습니다. 적는 것은 **정류장**뿐이고 —
*몇 시에 · 어느 맵의 · 어느 자리* — 사이 경로는 `StoryPathfinder` 가 그때그때 찾습니다.
가구를 새로 놓아 길이 막혀도 알아서 돌아가고, 길을 칠해 두면 그 길을 따라갑니다
(아래 [길 따라 걷게 하기](#길-따라-걷게-하기-path맵-레이어)).

자리도 좌표 대신 **이름**으로 부릅니다. 씬에 마커를 칠해 두면 그 칸이 그 이름이 됩니다.
맵을 다시 칠해서 광장이 세 칸 옮겨 가도 마커만 옮기면 되고 json은 손댈 필요가 없습니다.

### 작업 순서 (네 걸음)

1. **json에 이름을 적는다** — `"spot": "Plaza"`
2. **타일을 만든다** — Unity 메뉴 `Tools/FarmMVP/NPC 자리 타일 만들기`
   → json에 적힌 spot 이름마다 `Resources/Sprites/Tiles/Spot/Obj_Spot{이름}.asset` 이 생기고
   마커 팔레트(`Tiles/Markers/object.prefab`)에 하늘색으로 들어갑니다.
3. **씬에 칠한다** — 그 맵의 `Objects_{맵}` 레이어 (출구 마커를 칠하는 그 레이어)에 한 칸씩.
4. **검사한다** — `Tools/FarmMVP/NPC 스케줄 검사`
   → 안 칠한 자리, 알아들을 수 없는 `when`, 없는 초상화를 한꺼번에 알려 줍니다.

### 스케줄 json

```json
"schedule": {
  "routines": [
    { "when": "Storm", "stops": [
        { "time": "06:00", "map": "PigeonVillage", "spot": "Home", "facing": "Down" }
    ]},
    { "when": "Fall Sat", "stops": [
        { "time": "06:00", "map": "PigeonVillage", "spot": "Home" },
        { "time": "09:00", "spot": "Plaza", "wander": 3 },
        { "time": "13:00", "map": "Valley", "spot": "River", "wander": 2 },
        { "time": "17:00", "map": "PigeonVillage", "spot": "Tavern" },
        { "time": "23:00", "spot": "Home" }
    ]},
    { "when": "", "stops": [ ... ] }
  ]
}
```

**일과 고르기** — `when` 에 적은 말이 **전부** 맞는 첫 일과 하나만 쓰입니다.
우선순위 표를 외울 필요 없이 **특별한 날을 위에, 평범한 날을 아래에** 적으면 됩니다.
`when` 을 비우면 언제나 맞으므로 기본 일과는 **맨 아래**에 둡니다.

| 종류 | 쓸 수 있는 말 |
| --- | --- |
| 계절 | `Spring` `Summer` `Fall` `Winter` |
| 요일 | `Mon` `Tue` `Wed` `Thu` `Fri` `Sat` `Sun` (한 계절 28일 = 4주 정확히) |
| 날씨 | `Sunny` `Cloudy` `Rain` `Storm` `Snow` |

`"when": "Winter Sun Snow"` 처럼 섞으면 "눈 오는 겨울 일요일"이 됩니다.

**정류장 칸**

| 필드 | 뜻 |
| --- | --- |
| `time` | `"HH:MM"`. 그 자리로 **출발하는** 시각입니다 (도착이 아닙니다). 첫 정류장은 아침부터 거기 서 있습니다. 하루가 06:00에 시작하므로 `"01:30"` 처럼 그보다 이른 시각은 **자정을 넘긴 그 날 끝**입니다 |
| `map` | `LocationId` 이름. 비우면 **앞 정류장과 같은 맵** |
| `spot` | `Obj_Spot{이름}` 마커의 이름 |
| `x`, `y` | 마커 대신 좌표로 직접 찍고 싶을 때 (`spot` 대신) |
| `facing` | 도착해서 바라볼 방향. 비우면 걸어온 방향 그대로 |
| `wander` | 다음 시각까지 이 반경(칸) 안을 어슬렁거립니다. 0이면 가만히 |

`wander` 가 "살아 있는 느낌"을 담당합니다 — 광장에 `"wander": 3` 하나만 줘도 좌표를 한 개도
더 찍지 않고 NPC가 광장 주변을 돌아다닙니다.

### 길 따라 걷게 하기 (`Path_{맵}` 레이어)

정류장만 적으면 NPC는 **가장 짧은 길**로 갑니다 — 잔디밭이든 밭이든 직선으로 가로지릅니다.
흙길을 따라 다니게 하려면 그 길 위에 **`Path_{맵}` 레이어를 덧칠**하세요.
`Blocked_` · `Tillable_` · `Grass_` 와 같은 **마스크 레이어**라서 무엇을 칠하든 상관없고
(보이지도 않고 막지도 않습니다), 칠했는지만 봅니다.

- 레이어는 `Tools/FarmMVP/맵 레이어 만들기` 를 다시 누르면 맵마다 자동으로 생깁니다.
- 칠한 칸은 밟는 값이 **1**, 안 칠한 칸은 **3** 입니다. 그래서 NPC는 *가장 짧은* 길이 아니라
  *가장 싼* 길로 갑니다 — 세 배까지는 돌아가더라도 길을 탑니다. 값은
  `NpcScheduler.OnPathCost` / `OffPathCost` 에 있습니다.
- 한 칸도 안 칠하면 값이 전부 같아져서 예전처럼 최단거리로 걷습니다. 맵별로 하나씩 칠해 나가도 됩니다.
- 플레이어가 깐 **길 설치물(`wood_road`)** 은 칠하지 않아도 길로 칩니다. 농장에 길을 깔아 두면
  NPC가 그 위로 다닙니다.
- 길은 통행에 아무 영향이 없습니다 — 플레이어는 평소대로 아무 데나 다닙니다.

### 맵과 맵 사이 이동

정류장의 `map` 이 바뀌면 NPC는 **그 맵의 출구까지 걸어가서 실제로 넘어갑니다**. 넘어간 뒤에는
새 맵의 입구에서 다시 길을 찾아 이어 걷습니다 — 맵을 몇 개든 그렇게 건너갑니다.

- 나가는 자리는 ① `Obj_Exit{맵}` 출구 칸을 칠해 뒀으면 **그 칸**(다리·동굴 입구),
  ② 없으면 `MapGraph` 가 말하는 **그쪽 변**에서 가장 가까운 걸을 수 있는 칸입니다.
- 목적지가 **이웃 맵이 아니어도** 됩니다. `MapGraph.TryGetNextHop` 이 통로를 따라
  "먼저 어느 맵으로 나가야 하는지"를 찾아 주므로, 비둘기 마을 → 산 정상 같은 일과도
  계곡 → 산1 → … 순서대로 제 발로 건너갑니다.
- 걸리는 시간은 **실제로 걸은 시간**입니다. 적어 둘 값도, 어림잡을 값도 없습니다.

### 굴러가는 방식 — 모든 맵을 한꺼번에 굴린다

NPC의 자리는 **계산해서 짐작하는 값이 아니라 사실**입니다. 스케줄러가 (지금 있는 맵 + 그 안에서의
좌표)를 들고 있고, 플레이어가 어디에 있든 **매 프레임 똑같이** 앞으로 나아갑니다. 스타듀밸리가
모든 맵의 NPC를 항상 돌리는 것과 같은 방식입니다.

- 마을에서 보면 걸어 나가고, 계곡에서 기다리면 같은 시각에 입구로 들어옵니다 — 두 장면이 같은
  하나의 사실이라 어긋날 수가 없습니다. 도착 시각을 미리 어림잡거나 위치를 되돌려 맞추는 장치가
  아예 없습니다.
- 몸(`NpcActor`)은 **플레이어와 같은 맵에 있는 NPC에게만** 붙습니다. 몸은 그림을 고르고 앞뒤
  순서를 맞추는 일만 하고, 자리는 매 프레임 받아 씁니다.
- 화면 밖 맵의 지형은 `WorldGrid` 가 처음 한 번 떠 둔 **가벼운 지도**를 봅니다 (칠해 둔 레이어만
  — 벽·물·절벽·오브젝트·길·마커). 플레이어가 있는 맵만 진짜 `GameLocation` 을 봅니다.
- 그래서 화면 밖 지형은 **어림값**입니다. 플레이어가 베어 낸 나무나 새로 놓은 울타리는 모릅니다.
  플레이어가 그 맵에 들어서는 순간 진짜 지형으로 바뀌고, 벽 속에 서 있게 된 NPC는 가장 가까운
  걸을 수 있는 칸으로 옮겨집니다.
- 하루가 시작될 때(수면·불러오기) 그 날의 날씨·요일·계절로 일과를 고르고, 그 시각에 있어야 할
  자리에 한 번 세웁니다. 그 뒤로는 시계를 따라 저절로 굴러갑니다.
- 대화창이 떠 있거나 이벤트 연출이 도는 동안에는 멈춥니다. 연출이 끝나면 다시 일과로 돌아갑니다.
- 마커를 아직 안 칠했으면 NPC가 사라지는 대신 `home` (그것도 안 되면 맵 가운데)에 서고, 콘솔에
  한 번 경고가 뜹니다 — 마커를 칠하기 전에도 대화·선물을 시험해 볼 수 있습니다.

### 길이 막혔을 때

- 걷는 도중 **다음 칸에 플레이어가 서 있으면 멈춰 서서 기다립니다**. 길을 미리 정해 두더라도
  발을 들이기 직전에 한 번 더 확인하므로, 사람을 뚫고 지나가지 않습니다.
- 길목을 아예 막아 경로가 나오지 않으면 0.25초마다 다시 찾아보며 기다립니다.
- 어느 쪽이든 **10분(현실 7초)** 이 지나면 그냥 지나갑니다 — 길목에 서 있다고 NPC의 하루가
  멈추면 곤란하기 때문입니다. 값은 `NpcScheduler.Patience`.

### 아직 없는 것

- 실내(집 안)로 들어가는 문 통과는 다루지 않습니다 — 실내 맵을 정류장으로 적으면 그냥 그 맵에
  나타납니다.
- 화면 밖 맵의 지형은 칠해 둔 레이어만 봅니다 (위 참고).
- 날씨 연출(빗방울·눈)은 없습니다. `WeatherSystem` 이 값만 정합니다.

## 4. 날씨

날씨는 **저장하지 않고 날짜에서 계산합니다** (계절과 같은 원칙). 세이브에는 게임마다 한 번 뽑는
씨앗(`GameData.weatherSeed`) 하나만 들어갑니다. 그래서 며칠 뒤 날씨까지 미리 알 수 있고
(일기예보를 만들기 쉽습니다), 세이브가 어긋날 일이 없습니다.

- 계절별 확률은 `WeatherSystem.Chances` 표 한 곳에 있습니다. 겨울은 비 대신 눈입니다.
- 축제처럼 날씨를 못 박고 싶은 날은 `WeatherSystem.Fixed` 에 한 줄 적습니다.
- 지금 날씨는 `game.Today` 입니다.
